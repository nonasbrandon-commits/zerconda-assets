# Unified town actions and touch input

One registry presents nearby doors, seats, vehicles, home options, apartment floors, tower/elevator actions, café/showroom entry, showroom car details, golf and club activities. Original controls remain as hidden callback sources so the underlying action runs once through the same code. Visible proxies are real buttons, have accessible labels and at least 44px touch targets. Direct scene taps/clicks select a nearby projected interaction target. F activates the leading available action; existing shortcuts remain available.

On touch/pen, a short tap selects an action without locomotion. Holding the scene for 240ms walks forward; dragging changes the view while holding; release, pointer cancellation, capture loss, blur and page hide stop the gesture. Buttons and dialogs never start movement. Holding can stand the player from a seat and cancels dancing. Desktop dragging and WASD remain supported. The former mobile arrow pad is removed. Walk/Run, Map, Chat (in club), Reset and Beach are touch controls. Text input suspends movement. Safe-area/viewport sizing, 16px form controls and scrollable action/dialog panels support small screens and on-screen keyboards. The map canvas is contained in its own panel; chat can collapse without disconnecting. Coarse-pointer rendering uses a 1x pixel ratio cap and 1024px sunlight shadow map.

Browser validation covers short tap vs hold, moving/turning/releasing/cancelled touch, proxy activation without movement, narrow-screen fit, direct desktop scene click on a home door, home/garage/café/club entry and exit, apartment floors, tower up/down/exit, public seat/stand, showroom and vehicle entry/exit, golf, dance, pool modal and a touch-scored dart. Physics tests remain passing. Full-world functional checks use real input events with WebGL rendering stubbed after initial setup to separate UI/physics checks from software-GPU throughput; rendered house/room and mobile UI smoke checks are separate.
